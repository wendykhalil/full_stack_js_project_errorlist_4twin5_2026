# ML Feature — Real Machine Learning Models in BMP.tn

> **Requirement satisfied:** At least one feature powered by a real ML model trained/configured within the project.
> **No third-party AI API (ChatGPT, Gemini) is used.** All models are trained from scratch using scikit-learn inside the project's own `ml-service/` folder.

---

## 1. Overview

BMP.tn includes a **Python Flask microservice** (`ml-service/`) that trains, persists, and serves **four independent scikit-learn machine learning models**. These models are loaded at startup from `.joblib` files, retrained on demand, and called by the Node.js backend via HTTP. A fifth component is a pure rule-based fraud detection engine (no model file).

```
ml-service/
├── app.py                  ← Flask API (port 5001)
├── train.py                ← trains model.joblib
├── train_duration.py       ← trains duration_model.joblib
├── train_pricing.py        ← trains pricing_model.joblib
├── train_delay.py          ← trains delay_model.joblib
├── dataset.py              ← generates data.csv (product classifier)
├── duration_dataset.py     ← generates duration_data.csv
├── pricing_dataset.py      ← generates pricing_data.csv
├── delay_dataset.py        ← generates delay_data.csv
├── fraud_detection.py      ← rule-based fraud engine (no .joblib)
├── smart_analytics.py      ← analytics engine (numpy/pandas, no .joblib)
├── model.joblib            ← trained product classifier
├── duration_model.joblib   ← trained duration regressor
├── pricing_model.joblib    ← trained pricing regressor
├── delay_model.joblib      ← trained delay risk classifier
├── classes.json            ← ["BEST_SELLER","NORMAL","RESTOCK","UNDERPERFORMING"]
└── requirements.txt        ← flask, scikit-learn, numpy, pandas, joblib
```

**Stack:** Python 3 · Flask 3.0.3 · scikit-learn ≥ 1.3.0 · numpy ≥ 1.24.0 · pandas ≥ 2.0.0 · joblib ≥ 1.3.0

## 2. The Four ML Models

### Model 1 — Product Performance Classifier (`model.joblib`)

**What it does:** Classifies each supplier product into one of four business categories to drive restocking and pricing decisions.

**Algorithm:** `RandomForestClassifier` inside a scikit-learn `Pipeline`

```python
# train.py — exact code
pipeline = Pipeline([
    ("scaler", StandardScaler()),
    ("clf", RandomForestClassifier(
        n_estimators=200,
        max_depth=12,
        min_samples_leaf=3,
        class_weight="balanced",
        random_state=42,
        n_jobs=-1,
    )),
])
pipeline.fit(X_train, y_train)
joblib.dump(pipeline, "model.joblib")
```

**Input features (4 numeric):**

| Feature | Type | Description |
|---------|------|-------------|
| `price` | float | Product price in TND |
| `stock` | int | Current stock quantity |
| `orders` | int | Total orders received |
| `rating` | float | Average customer rating (0–5) |

**Output classes (`classes.json`):**

```json
["BEST_SELLER", "NORMAL", "RESTOCK", "UNDERPERFORMING"]
```

| Label | Business meaning |
|-------|-----------------|
| `BEST_SELLER` | orders > 80 AND rating > 4.0 — high demand, good rating |
| `RESTOCK` | stock < 10 AND orders > 30 — demand outstrips supply |
| `UNDERPERFORMING` | orders < 10 — slow mover |
| `NORMAL` | everything else — stable |

**Training data:** `data.csv` — 1,400 rows (350 per class), perfectly balanced, generated by `dataset.py` using `numpy.random` with seed 42.

**Train/test split:** 80/20 with `stratify=y`

### Model 2 — Project Duration Predictor (`duration_model.joblib`)

**What it does:** Predicts how many days a construction project will take to complete.

**Algorithm:** `RandomForestRegressor` inside a scikit-learn `Pipeline`

```python
# train_duration.py — exact code
pipeline = Pipeline([
    ("scaler", StandardScaler()),
    ("regressor", RandomForestRegressor(
        n_estimators=200,
        max_depth=15,
        min_samples_leaf=2,
        random_state=42,
        n_jobs=-1
    ))
])
pipeline.fit(X_train, y_train)
joblib.dump(pipeline, "duration_model.joblib")
```

**Input features (6):**

| Feature | Encoding | Values |
|---------|----------|--------|
| `project_type_encoded` | LabelEncoder | house=0, renovation=1, commercial=2, landscaping=3 |
| `size_sqm` | float | Project area in m² |
| `num_workers` | int | Number of workers assigned |
| `location_encoded` | LabelEncoder | rural=0, suburban=1, urban=2 |
| `materials_encoded` | LabelEncoder | basic=0, standard=1, premium=2 |
| `complexity` | int 1–5 | Project complexity scale |

**Output:** `duration_days` (continuous integer — regression)

**Training data:** `duration_data.csv` — 2,000 rows generated by `duration_dataset.py`

**Evaluation metrics:** MAE (Mean Absolute Error in days) + R²

**What it does:** Predicts whether a project is at HIGH, MEDIUM, or LOW risk of being delayed.

**Algorithm:** `RandomForestClassifier` inside a scikit-learn `Pipeline`


**Input features (11 — the most complex model):**

| Feature | Encoding | Description |
|---------|----------|-------------|
| `project_type_encoded` | int | house/renovation/commercial/landscaping |
| `size_sqm` | float | Project area |
| `num_workers` | int | Team size |
| `location_encoded` | int | rural/suburban/urban |
| `materials_encoded` | int | basic/standard/premium |
| `complexity` | float 1–5 | Project complexity |
| `budget_tnd` | float | Total budget in TND |
| `requested_duration` | int | Client's requested duration (days) |
| `artisan_experience` | float | Artisan experience in years |
| `season_encoded` | int | winter=0/spring=1/summer=2/autumn=3 |

**Fallback:** If `delay_model.joblib` fails to load, `app.py` uses `_fallback_delay_risk_assessment()` — a 400-line deterministic scoring function that computes risk without any model file.

```python
    pipeline = joblib.load(MODEL_PATH)
    with open(CLASSES_PATH) as f:
        classes = json.load(f)

pipeline, CLASSES = load_model()
```

All four models are loaded into memory once at startup. If a `.joblib` file is missing, the corresponding training script is called automatically.

### Prediction Flow (product classifier)

```python
# app.py — _predict_one()
def _predict_one(features_array):
    label      = pipeline.predict(features_array)[0]
    proba      = pipeline.predict_proba(features_array)[0]
    confidence = float(round(proba.max(), 4))
    proba_dict = {cls: float(round(p, 4)) for cls, p in zip(CLASSES, proba)}
    recommendation = RECOMMENDATIONS.get(label, "Analysez ce produit manuellement.")
    return label, confidence, proba_dict, recommendation
```

## 5. How Node.js Calls the ML Service

### Call chain for AI Insights (Supplier Dashboard)

```
Browser (FournisseurDashboard)
  → GET /api/supplier/ai-insights
        ↓
  supplier.routes.js
        ↓
  aiInsights.service.js
    collectProductMetrics(supplierId)
      → Product.find({ supplierId })          ← real MongoDB query
      → Order.aggregate([...])                ← real order counts
        ↓
  ml.client.js
    predictBatch(products)
      → POST http://localhost:5001/predict-batch
        ↓
  Flask app.py
    pipeline.predict() + pipeline.predict_proba()
        ↓
  Response: [{ label, confidence, probabilities, recommendation }]
```

### ml.client.js — the HTTP bridge

```javascript
// backend/src/modules/supplier/ml.client.js
const ML_BASE_URL = process.env.ML_SERVICE_URL || 'http://localhost:5001';

async function predictBatch(products) {
  const res = await fetch(`${ML_BASE_URL}/predict-batch`, {
    method:  'POST',
    headers: { 'Content-Type': 'application/json' },
    body:    JSON.stringify({ products }),
    signal:  AbortSignal.timeout(8000),
  });
  const data = await res.json();
  return data.results || [];
}

async function retrainModel(products) {
  const res = await fetch(`${ML_BASE_URL}/retrain`, {
    method:  'POST',
    headers: { 'Content-Type': 'application/json' },
    body:    JSON.stringify({ products }),
    signal:  AbortSignal.timeout(60000),  // retraining takes longer
  });
  return await res.json();
}
```

```
Browser → POST /api/supplier/ai-retrain
               ↓
  supplier.routes.js → retrainAiModel(req.user._id)
               ↓

               ↓
```

### Delay Risk Dataset (`delay_dataset.py`)

2,000 samples. Each sample computes a `delay_risk_score` from:
- Timeline pressure: `requested_duration / realistic_duration` ratio
- Budget pressure: `budget_tnd / estimated_cost` ratio
- Experience factor: `artisan_experience` years
- Complexity factor: `complexity` 1–5
- Team size vs optimal team size
- Seasonal weather risk

Score thresholds: > 0.6 → HIGH, > 0.35 → MEDIUM, else LOW.

## 8. Frontend Integration

The ML predictions are surfaced in the **Supplier Dashboard** (`/fournisseur` role):

- **AI Insights panel** — calls `GET /api/supplier/ai-insights` → displays each product with its predicted label (BEST_SELLER / RESTOCK / NORMAL / UNDERPERFORMING), confidence score, probability breakdown, and French recommendation text
- **Retrain button** — calls `POST /api/supplier/ai-retrain` → sends real product data to the ML service, retrains the model, invalidates the 5-minute cache, returns accuracy and sample count
- **Model metadata** — calls `GET /api/supplier/ai-model-meta` → displays last training date, samples used, accuracy

The **Artisan ML Predictions page** (`/artisan/ml-predictions`) calls:
- `POST /predict-duration` → estimated project duration in days
- `POST /predict-pricing` → estimated project cost in TND
- `POST /predict-delay-risk` → delay risk level with contributing factors

The **Admin Fraud Analytics page** (`/admin/fraud-analytics`) calls:
- `POST /api/fraud/scan/artisan/:id` → fraud score + indicators for a specific artisan
- `POST /api/fraud/scan/project/:id` → fraud score + indicators for a specific project
- `POST /api/fraud/scan/batch` → batch scan of artisans or projects
